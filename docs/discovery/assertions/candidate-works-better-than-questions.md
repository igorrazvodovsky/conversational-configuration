# Showing a candidate works better than asking a sequence of questions

Showing a valid candidate to react to works better than asking a sequence of questions.

If this fails, the conversational surface is decoration.

*Evidence today.* Strong in the recommender literature (critiquing surveys), untested here.

*How we would know it is wrong.* Users ignore the proposal and answer as if interrogated, or the proposal anchors them into accepting bad defaults.

*Status.* Feasible as of the 2026-08-20 walkthrough: every scenario reached a priced valid candidate to react to, and the agent proposed one unasked in three of the five. How people respond to it is untouched by one author-run pass. One edge the claim has to survive: the candidate is not durable. An ordinary revision drops it, and the sheet reverts to an unpriced document until a completion is asked for again, so the thing the customer is meant to react to disappears at exactly the moment they react. That edge was removed the same day: a priced agreement completes again across a change, so the candidate survives being reacted to.

*What rests on it.* The initiative default — *propose first, once anchored* — was chosen partly because waiting until asked abandons this claim without testing it ([../models/Conversation moves.md](../models/Conversation%20moves.md) §6). A bare minimal-core ripple was rejected for pushing the user back into the question sequence this claim exists to avoid ([../models/Ripple storyboard.md](../models/Ripple%20storyboard.md) §2).
