# Generated in-chat controls work better than free text

Generated in-chat controls work better than free text when the user lacks vocabulary.

*Evidence today.* Chen et al. 2025 shows large margins on comparison-heavy tasks ([interaction literature](../../research/interaction-literature.md)).

*How we would know it is wrong.* Users type over the controls, or controls fragment the conversation into a form in a window.

*Status.* In the 2026-08-20 walkthrough the controls were used rather than typed over, and they carried monthly deltas that free text couldn't. The second failure mode appeared in a form this note didn't anticipate: applying a control is a message, and the message spelled the catalogue's value codes in the customer's own bubble, which is the vocabulary the surface exists to spare them ([elicitation uses the building's vocabulary](../principles/elicit-in-the-buildings-vocabulary.md)). The controls also rendered ruled-out options disabled with no rule, so the surface meant to supply vocabulary supplied unexplained refusals with it.

*What rests on it.* The chatless geometry was set aside because it makes this claim untestable, and the *controls accelerate, never gate* rule exists to keep the second failure mode away ([Surface architecture](../models/Surface%20architecture.md), *The option field* and *Edges this model does not settle*).

This is the one research thread that became an assertion rather than a principle: a claim to test rather than a rule to decide by ([research index](../../research/README.md)).
