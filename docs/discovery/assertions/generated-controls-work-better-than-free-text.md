# Generated in-chat controls work better than free text

Generated in-chat controls work better than free text when the user lacks vocabulary.

*Evidence today.* Chen et al. 2025 shows large margins on comparison-heavy tasks ([../../research/interaction-literature.md](../../research/interaction-literature.md)).

*How we would know it is wrong.* Users type over the controls, or controls fragment the conversation into a form-in-a-window.

*Status.* In the 2026-08-20 walkthrough the controls were used rather than typed over, and they carried monthly deltas that free text could not. The second failure mode appeared in a form this note did not anticipate: applying a control is a message, and the message spells the catalogue's value codes in the customer's own bubble, which is the vocabulary the surface exists to spare them ([elicitation uses the building's vocabulary](../principles/elicit-in-the-buildings-vocabulary.md)). The controls also render ruled-out options disabled with no rule, so the surface that was meant to supply vocabulary supplies unexplained refusals with it.

*What rests on it.* The chatless geometry was set aside because it makes this claim untestable, and the *controls accelerate, never gate* rule exists to keep the second failure mode away ([../models/Surface architecture.md](../models/Surface%20architecture.md) §1, §3).

This is the one research thread that became an assertion rather than a principle: a claim to test rather than a rule to decide by ([../../research/README.md](../../research/README.md)).
