# Parallel drafts — design

Rules drafts: the store shape and its read-time adapter, the one door into history, the tools and state mirrors that move the workspace, and the canvas switcher. Read it before touching any path that changes which draft is current.

Status: implemented, against [requirements.md](requirements.md). One known gap is in *Open, deliberately*.

## Vocabulary

`Configuration.candidate` keeps its meaning: the solver's completion of the current choices, written by `propose_completion` and read by `resolveValue()` as the last fallback. The new entity is a *draft*, one whole configuration among several in a workspace. So a workspace holds drafts, and each draft has a candidate. The two senses of "candidate" that the discovery layer runs together ([problem-framing](../../discovery/problem-framing.md), *Open questions the framing does not settle*, against constitution #7) are separated here in favour of the code's existing meaning, and *draft* is chosen to sit in the contract genre the canvas already renders — recitals, operative terms, schedules ([agreement-document](../agreement-document/design.md)).

## Store shape

The `agent/src/workspace_store.py` record becomes:

```
{id, name, drafts: [{id, name, forkedFrom, configuration, log}], currentDraftId, threads, updatedAt}
```

`configuration` and the draft's record of what was done to it move off the record and onto each draft. That record was a pair of snapshot stacks under `history` and is a `log` of typed actions under [action-log](../action-log/design.md); everything this spec says about it holds either way. `threads` and `name` stay at the workspace, because conversations are views onto the installation rather than onto a draft. Draft ids are minted like workspace ids.

Unlike the workspace's name, a draft's is never `null`. The tools address drafts by name, so a nameless draft would be one the agent can't switch to, compare or discard. `fork_draft` therefore requires its name, and the read-time adapter supplies "Original" for the draft it adapts. This is where the workspace naming precedent stops applying: a workspace is addressed by its id from a route, and can afford to wait for a name.

`forkedFrom` holds the id of the draft this one was copied from, and is `null` on the draft a workspace opens with. Source traceability back to the origin is the first thing every shipped branching implementation does — Manus prints a breadcrumb, ChatGPT an origin label ([branching in AI UIs](../../research/branching-in-ai-uis.md), *What the pattern libraries prescribe*) — and a document that says nothing about where it came from would be the one object in this system that doesn't, in a prototype where every individual value quotes its source ([choice-provenance](../choice-provenance/requirements.md)). It costs a field and a phrase beside the draft's name in the switcher. The requirements don't demand that the phrase be shown; recording the parent is what makes showing it a later decision rather than a migration. Discard leaves children pointing at an id that resolves to nothing, and the field is read for display only, so an unresolvable parent renders as no lineage at all rather than being repaired on the way out. Rewriting a grandchild's parentage on discard would assert a lineage that never existed.

Draft names are addresses, so they are unique and resolved case-insensitively: the agent reaches a draft through a customer's sentence, and "premium" is the draft it named "Premium". Storage keeps the name as given, and a fork whose name is already taken is refused by the same comparison the lookup uses.

*A record with no `drafts` key is adapted on read*, in `_read`, so every path — `get_workspace`, `list_workspaces`, the HTTP routes, the frontend — sees one shape. Its `configuration` becomes a single draft named "Original" with no parent, and its `frames` are dropped. So is the `history` it was written with, once [action-log](../action-log/design.md) replaced the snapshots, and for the same reason. This is a read-time adapter rather than a migration script: `agent/data/workspaces/` is gitignored local data, and the [agreement-workspace](../agreement-workspace/requirements.md) precedent for pre-feature records is to let them lapse rather than convert them. Frames can't be converted honestly anyway, because synthesizing the missing provenance would re-source every value to `user`, which is the defect this feature removes.

## The write path, and what a switch must not touch

`save_configuration` wrote history at the record. Under drafts it diffs against the *current draft's* configuration and writes to that draft's own record. A switch also changes what the workspace's current configuration is, so routing a switch through the same function would burn an undo slot and let a subsequent undo walk backwards into a state belonging to a different document.

The separation is structural rather than a flag. `fork_draft`, `switch_draft` and `discard_draft` are their own store functions that rearrange drafts and move `currentDraftId` without ever calling `save_configuration`. Content changes reach the record through the doors [action-log](../action-log/design.md) rules, and structural moves reach none of them. `HISTORY_DEPTH` stays 10, now per draft.

*A fork starts with an empty record rather than a copy of its source's.* Copying looked like the more faithful reading of "a draft is a whole configuration", and it is wrong for a reason the requirements state directly: a fork must not discard a redo tail or inherit one, and a copied record hands the new draft a *redo* of a batch that was never applied to it. Nothing is lost by not copying. The source keeps its ten batches, and the fork's own record begins with the first action taken on it, which is what "the last change applied to this draft" means. The visible consequence is that the canvas's undo control is absent on a fresh fork until something is applied to it.

`discard_draft` refuses the draft being worked on, and that one check covers the last-draft rule too, because the only draft of a workspace is always the current one. The message names which case it is.

Last write wins and no locking are unchanged, and `_stamp` still stamps the workspace and the writing conversation.

## Agent state and tools

`AgentState.configuration` keeps its meaning and its shape: it is the current draft's configuration. Every existing tool, the canvas, `resolveValue()` and the register are therefore untouched by this feature. They read the current draft without knowing that is what they are doing, which is what keeps the change small (constitution #3, #10).

Two mirrors ride alongside, read only for chrome: `current_draft_id`, and a `drafts` list of `{id, name, price}`. They are built by one `_mirrors(record)` helper that also returns the undo depths, from the record the write just produced, and every path that moves the workspace calls it — the three structural tools and the undo and redo restores included, not only `_commit`. A switch that left the depths behind would offer an undo belonging to the other document, and a restore that left the drafts behind would show the wrong price beside the draft it just repriced. The precedent is `workspace_name` and the undo depth mirror: state the canvas renders controls from, never a second source of truth. Both are declared on `AgentState`, because the AG-UI adapter filters each state snapshot to the graph's output schema and drops undeclared keys on the way to the browser with no error at either end ([CopilotKit surface](../../research/copilotkit-surface.md), *State reaches the canvas as snapshots, never as deltas*).

A draft's `price` is nullable. Price lives on `Configuration.candidate`, and `_keep_candidate` drops the candidate whenever a choice diverges from it. Since the prototype walkthrough, a transition that invalidates a candidate completes again on the same objective in the same batch (`_repriced`, [agent-tools](../agent-tools/design.md)), so the null case narrowed from *edited since its last completion* to *never completed at all*. The switcher shows such a draft by name alone. Solving the other drafts to fill the gap is rejected: the solver is called by tools acting on the current draft (constitution #1), and pricing every draft to draw a menu would put solver calls behind a render.

The tools, replacing the three frame tools:

- `fork_draft(name)` copies the current draft's whole configuration into a new draft and makes it current. The `name` argument is the agent's, supplied from the conversation. The docstring carries when to call it, and the system prompt carries the two silences — never ask for a name, never announce the naming — per [where guidance lives](../agent-tools/design.md). It returns a `Command` updating the mirrors and nothing else: the forked configuration is byte-identical to the one it came from, so there is no content change to record, and the store's structural path reaches no draft's record in the first place.
- `switch_draft(name)` moves `currentDraftId`. No configuration is written, and nothing is re-sourced. This is what replaces `adopt_frame`, and the wholesale re-attribution to `user` disappears with it.
- `discard_draft(name)` removes a non-current draft, and refuses on the last one.
- `compare_drafts(a, b?)` defaults `b` to the current draft. The payload is the old `frame_comparison` with `kind` renamed to `draft_comparison` and each side named by its draft. Because both sides are full configurations rather than assignment-plus-price, the "—" fallback for a side lacking stored footprint applies only to pre-feature data. The footprint delta ships twice, raw as `footprintDelta` and formatted as `footprintDeltaText` through `_format_co2`: the card renders the string and the docstring tells the agent to quote it, because left to format the raw figure themselves the two runtimes diverged, with the card reading 1.5 t CO₂e where the sentence beside it read 1,529 kg CO2e. That is the reason `_format_co2` exists at all, extended here from prose tool messages to a JSON payload.

  Each side is compared by its *candidate*, the priced whole the solver returned, so a draft edited since its last completion has nothing to compare with. The tool says which draft and what to do about it rather than solving for it: the solver answers for the draft being worked on (constitution #1), and pricing another draft behind a comparison would be a solve the customer never asked for. The tool reads the store for the other draft and the run's own state for the current one, so the column labelled as the current draft is the sheet the customer is looking at. Comparing a draft with itself is refused by name. The pure function `draft_comparison(a_name, a_config, b_name, b_config, b_is_current)` is store-free and unit-tested.

The four-step cheapest-versus-greenest sequence taught by the `propose_completion` docstring ([environmental-footprint](../environmental-footprint/design.md)) rewrites onto the new names and otherwise stands.

Two things outside the tools shape what the agent knows. `get_configuration` ended with a "Saved frames: …" line built from `_frames(config)`, and that becomes the draft list, naming the current one, so the agent's read of state says which document it is looking at. And the system prompt gains a drafts framing beside the one [agreement-workspace](../agreement-workspace/design.md) added about other conversations: the agreement may exist as several drafts, changes land on the current one, and forking is what to offer when the customer wants to try something without giving up what they have.

## Frontend

The canvas head gains the current draft's name and a switcher listing the others with their prices — the frames strip's information, relocated from a compare-trigger under the price header to a navigation control at the document's identity.

Fork, switch and discard dispatch visible structured messages in the established grammar, mapped onto one atomic tool call each, like undo's controls and unlike the hidden `Canvas edit:` path. Switching changes what the whole document says, so the chat has to carry it. Because conversations are views onto the workspace rather than onto a draft, one transcript will hold turns that acted on two documents, and the visible sentence is the marker that keeps that readable: a transcript that changes what it refers to with nothing recording the change is the branching genre's first named failure mode ([branching in AI UIs](../../research/branching-in-ai-uis.md), *What the pattern libraries prescribe*).

The switcher's menu also carries the compare trigger the frames strip had, as *Compare with «other draft»* per other draft, beside *Keep this and start another* and a destructive *Discard «other draft»*. Compare is the one move here with a precondition: `compare_drafts` needs a priced candidate on *both* sides, and a draft nobody has asked a completion for has none, so the item is disabled and carries *no price*, where the menu already shows the absence by omitting the figure. When the draft being worked on is the unpriced one, no per-draft item can run, and the whole group collapses to a single disabled *Compare — no price*. It is disabled rather than hidden, because a move that vanishes between two openings of the same menu reads as a bug, and discard is unaffected either way. Where a comparison is *placed* is decided — a canvas mode, with the chat keeping one sentence ([Comparison view](../../discovery/models/Comparison%20view.md)) — and not yet built. What lives here is the affordance that opens one.

Two rules from [chat-surface](../chat-surface/design.md) govern the switcher and are the likeliest source of a silent breakage.

- It is a menu, so it mints React ids, so it may not join the hydrated tree. It mounts a tick later, exactly as the chat header's mode and conversation menus do. Sharing markup with the existing conversation menu has to be done as a class string, not as a component lifted above id-minting descendants.
- It reads agent state through props from the canvas, which already subscribes, and calls no hook of its own beyond the hydration flag. Nothing on the workspace page may call `useAgent()`.

*The first rule bites harder here than in the chat header, and the shipped switcher renders nothing at all until it has mounted.* Following the header's pattern literally — a plain button before hydration, the menu after — reported a hydration mismatch on every load, on the `useId` values of the schedules' collapsibles, which sit under the header in the same tree. The cause isn't the menu but the button: the canvas hydrates after the workspace seed has landed, so the client's hydrating render already has `drafts` in state and draws a node the server's render, which has no agent state and so no drafts, didn't. An id-minting descendant under an inserted node is the hazard [chat-surface](../chat-surface/design.md) names, and here the inserted node appears *because* server and client disagree about whether there is a draft to name. Returning `null` until the mount effect has run makes the two agree, and the switcher appears a tick later with everything else the seed brought.

The hydration seed in `use-workspace-attachment.ts` carries the mirrors too. It writes `workspace_id`, `configuration` and the undo depths into state on attach, and it is the only path for the two new fields: a thread that has never run replays no snapshot, and one that ran before this feature replays a snapshot of an `AgentState` with no `drafts` key in it ([CopilotKit surface](../../research/copilotkit-surface.md), *State reaches the canvas as snapshots, never as deltas*). Seeding the current draft's configuration without `current_draft_id` and `drafts` would leave the document unnamed and the switcher empty until the customer's first message.

The hook's workspace-configuration precedence moves with the store shape. Its `want` was `stableStringify(record.configuration)`, and under drafts the comparison target is the current draft's configuration, selected out of the record `fetchWorkspace` returns. That is a small change in a hook whose traps are documented in [agreement-workspace](../agreement-workspace/design.md), and it is the second thing to get right there after the seed.

*The precedence subscriber compares the pair `(current_draft_id, configuration)`, not the configuration alone*, and this was found in the browser rather than in review. The connect that follows a page load delivers the thread checkpoint's state, and a checkpoint written before a fork carries the configuration of the draft the fork came from, byte-identical to the fork's. Comparing content alone, the subscriber saw no difference, left the checkpoint's `current_draft_id` standing, and the canvas named the wrong document while showing the right one. The rule is the same one the staleness check needs, for the same reason, and it is cheap because `current_draft_id` is declared on `AgentState` and so rides in the checkpoint.

*That pair also decides whether a reopened conversation's cards may still act.* A fork produces a draft byte-identical to the one it came from, so content equality stops being evidence of draft identity for exactly as long as the fork goes unedited — the window in which a customer is most likely to reopen the conversation the fork came out of. A card left live in one conversation, with the fork taken in another, would pass the staleness check on reopening and apply to the fork. So the comparison is over the pair `(current_draft_id, configuration)`, which costs nothing, since `current_draft_id` is declared on `AgentState` and the thread checkpoint carries it. Unpinned conversations are what make this reachable at all, because the branching genre keeps a branch's transcript to itself ([branching in AI UIs](../../research/branching-in-ai-uis.md), *What this means for the prototype*), and of everything that trade gives up, this is the part that produces a wrong action rather than a confusing display.

The reason such a card gives is the drafts' names. [Agreement-workspace](../agreement-workspace/design.md) has the inert card state why it can't act instead of only dimming, and under drafts the sentence can be specific — *this conversation was working on Original; the current draft is Premium* — which tells the operator what to do about it, where "the agreement has moved on" only tells them something happened. Both names are to hand where the sentence is formatted, in the hook rather than the card: the current one from the record, and the conversation's own by resolving the `current_draft_id` in its checkpoint against the record's drafts. That is the same pair the staleness check compares, and it reaches the card as the reason string [agreement-workspace](../agreement-workspace/design.md) puts on `StaleThreadContext`. Saying it well matters more here than it did there: the shipped feature needed a second conversation to have written to the workspace before anything went inert at all, where forking and switching are cheap moves an operator makes on purpose and often.

Two edges. *The conversation's draft may be gone* — C1 worked on a draft since discarded — and then there is no name to resolve, so the sentence falls back to the workspace-level wording, which is still true. *And the sentence says "was working on" in the singular*, which holds only because a card that predates a switch made inside its own conversation is already inert by the any-user-message rule and never reaches this path. Only tail cards do, and a tail card's draft is the checkpoint's draft. That is true of the inert rule as it stands, and would quietly stop being true if the rule were loosened.

Carrying that reason is the type change [agreement-workspace](../agreement-workspace/design.md) specified and this feature builds: `StaleThreadContext` holds the reason string or `null` rather than a boolean, `useCardDispatch` returns it beside `inert`, and `CardShell` renders it as a line inside the card. The other two inert conditions pass nothing and look exactly as they did. The page's shared-attention context entry says the same sentence to the agent.

`FrameComparison` becomes `DraftComparison` with the renamed payload check, and its two-column layout and both deltas are unchanged. Two things move with the meaning: each column is headed by its draft's name, with the current one marked rather than renamed to "current", and the button reads *Work on «draft»* and dispatches a switch, so taking a side no longer replaces anything.

## Alternatives considered

- *Pin each conversation to a draft.* This is the shipped pattern in the one genre that has tried it, where VS Code and Cursor checkpoints restore conversation and files together ([living-document undo](../../research/living-document-undo.md)). Rejected because it contradicts the [agreement-workspace](../agreement-workspace/requirements.md) ruling that conversations are ephemeral views onto the installation, and because it would restructure the entry-resolution logic in `use-workspace-attachment`, the most trap-dense hook in the codebase, for a benefit this feature doesn't need.
- *Keep history at the workspace and let it cover structural moves.* Attractive for uniformity, since the [move inventory](../../discovery/models/Conversation%20moves.md) says every move reverses, but an undo taken after a switch would restore a state belonging to another document while the user looks at this one.
- *Keep frames beside drafts.* Two mechanisms for one idea (constitution #10).
- *Carry a switch as an AG-UI state delta rather than a snapshot.* The transport needs nothing added for this feature, for three independent reasons ([CopilotKit surface](../../research/copilotkit-surface.md), *State reaches the canvas as snapshots, never as deltas*). The LangGraph adapter emits whole snapshots and no deltas at all, so the delta path would have to be built rather than used. A switch replaces the configuration wholesale, which is what a snapshot already is, so the patch would restate the document. And a delta that fails to apply is caught and logged as a warning, leaving the canvas showing the previous draft with nothing marking it stale, against [always show a valid whole](../../discovery/principles/always-show-a-valid-whole.md). Size isn't part of the argument: a stored configuration measures 3–8 KB, and the whole set of drafts would still make an unremarkable snapshot. The reason to keep all but the current draft out of agent state is the mirror precedent, not bytes.
- *Fork from a point in history rather than from the current state.* Every shipped branching implementation forks at a visible message — hover the turn, branch from there ([branching in AI UIs](../../research/branching-in-ai-uis.md), *What ships*). The analogue here is forking at history entry *k*, and it is rejected for want of a surface rather than for difficulty: the canvas renders no history, [undo](../undo/requirements.md) excludes a visible history timeline, and the transcript isn't the state ([the canvas is the durable locus](../../discovery/assertions/canvas-is-the-durable-state.md)), so there is no point in history for the customer to put a finger on. Fork-from-current is what a document-side branch can offer, and undo remains the way back to an earlier state of one document.
- *Cap the number of drafts instead of allowing discard.* The cap would be an arbitrary number, and discard is the structural inverse of fork, which is the more honest mechanism. Proliferation is still the risk to watch: creation is cheap, every draft is visible in the switcher, and if drafts accumulate unread the affordance is wrong rather than the count.

## Testing

Store, in `test_workspace_store.py`: the read-time adapter, with frames dropped and a fork working afterwards; a fork carrying the whole configuration with its sources; editing one draft leaving the other alone; the fork's empty record; per-draft isolation under undo; a switch writing no entry and abandoning no redo tail; case-insensitive addressing; the duplicate-name and current-draft refusals; and drafts surviving a round trip. The assertions about what that record *holds* moved to [action-log](../action-log/design.md) when the snapshots did. Agent, in `test_configuration.py`: `draft_comparison` over two drafts, the missing-candidate refusal, per-side terms, and the footprint pair. 148 pass.

The Python grammar mirror gains the four sentences, and [comparing agreements](../../discovery/scenarios/comparing-agreements.md) exercises fork, compare and switch, reading the fork's name from the tool call's own argument, since the prompt forbids both asking for it and announcing it. `compare_refs.py` remains the only check that sees the docstring and prompt edits at all.

*Browser pass* (constitution #9), one workspace, two conversations, run 2026-08-17. Proposal → fork from the canvas switcher, with a visible sentence, one `fork_draft` call, the canvas renamed and no undo control on the fresh fork → premium service level applied on the fork through the ordinary canvas edit, with the store confirming the source draft untouched and its own history intact → the fork priced → compared from the switcher, both columns named and both deltas shown → *Work on Original* from the card, switching with nothing re-attributed → undo on Original reversing Original's last batch while the fork's history stayed put, and redo restoring it → a second conversation forking, and the first reopening with its card inert and naming both drafts → discard removing the draft and leaving the current one alone → cold reload naming the current draft before any message was sent. Two defects surfaced and were fixed in the pass: `undo_change` still read `record["configuration"]`, and the seed subscriber compared configurations without the draft id, both recorded under *Frontend*.

Not verified: dark theme, which has no in-app toggle and follows the system setting. The switcher is built from the same dropdown primitive and the same tokens as the chat header's menus, so this is a low risk rather than a checked one.

One known gap, from the same pass: a fork taken from the switcher in a *fresh* conversation gets a name with nothing behind it. The run produced "Draft from current", because the conversation it was told to name the draft from was empty. This isn't an edge case but the straight path from the chat header's *New conversation* button to the canvas's fork control, which is available in every conversation, including one with no turns in it. The rule that the agent names a draft and never asks is unchanged, and works whenever the conversation has said anything at all. There are two shapes of fix, neither taken here: instruct the agent for the empty case, or disable the switcher's fork until the conversation has a turn. The second is smaller and admits that a fork made before anything is said has nothing to be *for*. It wasn't patched with a placeholder name, which would be the frames strip's unnamed chip returning under another name.

## Open, deliberately

Where a comparison is placed, and how a two-objective comparison is laid out, are answered by the [comparison view](../../discovery/models/Comparison%20view.md), drawn after this feature landed. This feature gave it two real documents to lay out instead of a document and a snapshot, and the [pending amendment](../nonlinear-interaction/design.md) that would move comparisons document-side is unaffected either way.
